# NiveshNadi Brand System

## Name

NiveshNadi means investment river. The name is designed around flows: SIP inflows, STP transfers, SWP withdrawals, portfolio current, and long-term compounding.

## Tagline

Primary: Know the fund before you fund it.

Secondary: Mutual fund research, simplified.

## Visual identity

The logo is a 3D-style letter N shaped like a flowing river. The three streams represent SIP, STP, and SWP. The gold stroke represents long-term compounding and investor prosperity.

## Colors

- Deep ink: trust, research, institutional seriousness.
- River green: investor progress and disciplined flow.
- Research blue: analytics and evidence.
- Saffron gold: India, prosperity, and decision confidence.

## Tone

Simple, evidence-backed, calm, and protective. NiveshNadi should feel like a research companion, not a sales platform.

## Product simplicity rule

The default product should show the shortest useful path first: profile, find, verify, memo, and review. Advanced research depth should remain available, but it should sit behind intentional choices so a retail investor is not forced to understand every expert control on the first screen. Secondary market context should not compete with the first decision task in Simple View; keep it available in Full View or a later room. Step-specific rooms should not auto-stack adjacent advanced tools in Simple View; the user should explicitly choose the next room when they want more depth. Hash landings in Simple View should feel like entering one clean room, with hidden-room anchors ignored and a tight header offset so the previous section does not visually bleed into the target. Simple View should begin with one search box; category, risk, and sort controls belong in Full View unless the investor explicitly asks for more filtering. Starter searches may appear as tiny chips under the single search box, but they should populate the query rather than reintroduce multiple visible filters; small count badges may show the number of demo matches so the user understands the path size before clicking. When a search is active, show a small result count, the named top match, one top-match action, and clear action so the user understands the current state and next move without opening more controls. If a search has no matches, show a calm recovery state with one clear action and a few starter paths rather than a dead-end error.

In Simple View, the header should behave like a calm route map rather than a command center. Keep the brand present but compact, with reduced logo size, tighter vertical rhythm, and less chrome before the workspace. Show the five investor steps first, keep the workspace jump short and guided, and move expert, launch, backend, and founder controls into Full View. Full View may carry the complete workshop map for building, QA, and founder review. The first-screen route rail should be live, not decorative: it should tell the investor which simple step is active, what single next move matters, and one plain checkpoint question to answer before moving forward. Active step state should follow the room being viewed, while the selected-fund recommendation can remain separate as the next suggested move. When a main simple step is opened, the page should behave like one clean room and hide adjacent workshop sections until Full View is chosen. In that clean-room state, show one compact room cue with the room name, one task, and the next guided route so the investor does not feel lost after the workshop is hidden. The cue may include browser-local progress memory, a resume-last-room affordance, a fresh-start reset, and a save-review completion cue after all five guided rooms have been touched. The Review Vault may show a five-step Research Round Receipt, one direct save-round action, a post-save Next Review Cue, a compact Review Finish Line, and a Start Next Round action that preserves saved snapshots while clearing only guided-room progress, so the finish line, next calm checkpoint, and no-transaction boundary are visible, but it must count only guided-room visits and store only route IDs, never investor identifiers, notes, PAN, folio, account, or transaction data. After the route rail scrolls away, the Simple View header may retain one compact next-action cue, but it must be a single command and never a second toolbar. The selected-fund signal should include a plain-English takeaway, compact decision-readiness chips, one "Do next" action cue, and a visible, prioritized Now/Then/Final plan that shows whether evidence, peer comparison, and memo readiness are blocked or ready before the user opens more tools. Active route and plan states should be labeled in words such as Current or You are here, not only color. The route rail should have one full-width next-action command before supporting route chips and should appear before background desk status cards in the first fold. Export and copy controls should stay out of the Simple View decision path unless the user intentionally opens Full View.
